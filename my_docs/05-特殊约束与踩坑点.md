# 05 特殊约束与踩坑点

> 路径都相对仓库根目录 `/data/ruiqinchen/ray`。

## 1. 构建与环境

1. **`import ray` 依赖 C++ 产物。** 以下文件都由 bazel 生成，没有它们 `import ray` 或启动集群会失败：
   - `python/ray/_raylet.so`
   - `python/ray/core/src/ray/raylet/raylet`
   - `python/ray/core/src/ray/gcs/gcs_server`
   - `python/ray/core/generated/*_pb2.py`

   修改过 C++ 或 `.proto` 后，需要重新执行 `bazel run //:gen_ray_pkg`；只改了 proto 时执行 `//:gen_py_proto` 即可。生成规则见 `BUILD.bazel` L338-464、`gen_ray_pkg.py`。
2. **只改 Python 时用 `setup-dev.py`。** `python/ray/setup-dev.py` 会把 site-packages 里的子包换成指向源码的软链接，并把原目录备份为 `.bak`。这种模式下：
   - 不要直接 `pip uninstall ray` 或 `pip install -U`，要先 `rm -rf site-packages/ray`（`development.md` L132-140）。
   - `serve/generated` 这类生成物会被特意保留（`setup-dev.py` L86-112）。
3. **版本锁定：**
   - Python 只支持 3.10–3.14（`python/setup.py` L24）。
   - Bazel 只支持 7.5.0（`.bazelversion`）。
   - 依赖 lock 文件需要在 **x86_64 Linux + Python 3.11** 上生成。
4. **Bazel 资源占用大。** 机器内存不足时，在 `~/.bazelrc` 或 `.user.bazelrc` 中添加 `build --local_resources=memory=HOST_RAM*.5 --local_resources=cpu=4`。不要修改项目里的 `.bazelrc`（它会导入 `.user.bazelrc`，见 L275-278）。
5. **默认开启 `-Werror` 和 `-Wshadow`。** 见 `.bazelrc` L89-90、`bazel/ray.bzl` 中的 COPTS。新代码出现任何 warning 都会导致编译失败。
6. **平台差异：**
   - jemalloc 只在 Linux 上启用（`BUILD.bazel` L51-55）。
   - RocksDB 存储后端只支持 Linux。
   - 在 macOS 上需要先 `brew uninstall grpc protobuf`。
   - 在 macOS 或 Windows 上跑多节点需要设置 `RAY_ENABLE_WINDOWS_OR_OSX_CLUSTER=1`。
   - C++ API 测试无法在 macOS 上运行（`ci/ci.sh` L143）。
7. **psutil 循环导入报错**的处理方法：`rm -rf python/ray/thirdparty_files/ && pip install psutil`（`development.md` L454-479）。
8. **`ci/lint/lint.sh` L59 引用的 `ci/lint/format.sh` 在仓库中不存在**，所以 `lint.sh code_format` 无法直接使用，应改用 `pre-commit` 或 `lint.sh pre_commit`。

## 2. 运行时与代码层面

1. **单线程事件循环模型。** GCS、raylet 和 CoreWorker 的 RPC Handler 都会被 post 到 `instrumented_io_context` 上执行（见 `src/ray/rpc/grpc_server.h` L35-59 和 `client_call.h` L196）。Handler 中出现同步阻塞，会拖慢整个进程。
2. **plasma store 是 raylet 内部的全局单例线程**（`src/ray/object_manager/plasma/store_runner.h` L78）。每个 raylet 只能有一个实例，原因是 dlmalloc 只能全局使用。
3. **Ownership 模型：** 对象的 owner 是创建它的 worker。owner 退出后，它拥有的对象会丢失，只能通过 lineage 重建。写测试和排查问题时都要考虑 owner 的生命周期。
4. **Actor 创建任务的 `max_retries=0`**（`core_worker.cc` L2476）。Actor 的重启由 GCS 负责（`max_restarts`），不走任务重试。
5. **Actor task 不经过 raylet 调度**，由提交方直接推送给 actor worker。它依赖 GCS 推送的 actor 状态（`actor_task_submitter.cc` L298）。
6. **调度类名称已经变更。** 现在叫 `ClusterLeaseManager`/`LocalLeaseManager`/`LeaseDependencyManager`，不再是 `ClusterTaskManager`/`LocalTaskManager`。旧文档和博客里的名称已过时。
7. **`RAY_CONFIG` 配置机制**（`src/ray/common/ray_config.h` L72-101、`ray_config_def.h` L18-19）：
   - 新配置项写在 `ray_config_def.h` 中，带 `///` 注释，类型要能被 `ReadEnv` 解析。
   - 每个配置都可以用环境变量 `RAY_<name>` 覆盖。bool 类型只把 `"true"` 和 `"1"` 当作真。
   - 通过 `_system_config` 或 `config_list` 传入未知 key 时，进程会直接 FATAL（`ray_config.cc` L31-77）。
   - `ray_config_def.h` 只能被 `ray_config.h` include。
   - 内部开关写在 `ray_internal_flag_def.h`。
8. **GCS 存储后端**由 `RAY_gcs_storage` 决定，默认是 memory。配置了 Redis 地址时会自动切换到 Redis 持久化（`gcs_server.cc` L933-959）。GCS 容错依赖 Redis。
9. **`ray.workflow` 已移除**，import 时直接抛 RuntimeError（`python/ray/workflow/__init__.py`）。
10. **自动初始化：** 在没有调用 `ray.init()` 的情况下调用 `get/put/wait/remote` 等 API，会隐式执行 `ray.init()`（`python/ray/__init__.py` L208-247）。测试中可能因此意外启动集群。
11. **`_raylet.so` 以 `RTLD_GLOBAL` 方式加载，并通过版本脚本控制符号导出**（`src/ray/ray_version_script.lds`、`ray_exported_symbols.lds`）。如果新增的 C++ 符号需要被其他扩展使用，要检查导出规则。

## 3. 测试相关

1. pytest 默认超时 **180s**（`pytest.ini` L13），超过就算失败。慢测试需要在 BUILD 中设置 `size` 或单独标记 timeout。
2. 测试应使用 `shutdown_only`、`ray_start_*` 等 fixture，保证执行 `ray.shutdown()` 和 `reset_ray_address()`，避免集群泄漏到后续测试（`python/ray/tests/conftest.py` L562-603）。
3. 用 `python -m pytest` 运行，不要直接用 `pytest`，否则可能丢失 import 路径。
4. 新的 Python 测试文件需要注册到对应的 `BUILD.bazel`（`py_test_module_list`），并且必须带 `team:*` 标签。Ray Data 的测试必须放在 `python/ray/data/tests`（pre-commit 中 `data-tests-location` 检查）。
5. 在 Bazel 中运行 Python 测试不是 hermetic 的，CI 会禁用测试缓存（`.bazelrc` L205-233）。本地直接用 pytest 更快。
6. C++ 测试使用 asan 时只能 `--jobs=1`，使用 tsan 时会关闭 jemalloc。

## 4. 提交流程约束（`AGENTS.md`）

1. **DCO：** 每个 commit 都要 `git commit -s`。也可以运行 `./setup_hooks.sh` 安装自动签名钩子。
2. **pre-commit：** 版本为 `pip install -U pre-commit==3.5.0 && pre-commit install`。
3. **文档 URL 重定向：** 重命名、移动或删除 `python/ray/` 下的公共 API，或移动 `doc/source` 下的页面，都必须在同一个 PR 中更新 `doc/redirects/current.yaml`，并运行 `rtd-redirects validate`。
4. **依赖改动：** 只改 Layer 1 源文件，再重新生成 compiled 文件和 lock 文件；`requirements.txt` 与 `setup.py` 中的 `install_requires` 要同步修改。
5. **AI 辅助的 PR：** PR 描述中必须说明三点：为什么不与已有工作重复、执行了哪些测试命令及结果、使用了 AI 辅助。不要提交只修一个 typo 这类低价值 PR。
6. 合并上游时用 `git pull . upstream/master`，不要 rebase（`getting-involved.md` L117）。
7. 修改 `AGENTS.md` 需要单独提一个 PR。
