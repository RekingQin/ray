# 02 核心模块说明

> 路径都相对仓库根目录 `/data/ruiqinchen/ray`。

## 1. 模块依赖关系（分层）

```
+------------------------------------------------------------------+
|  AI Libraries: data / train / tune / serve / rllib / llm / dag   |
+------------------------------------------------------------------+
|  Python Core API: ray.init/remote/get/put/wait  (_private/worker)|
|  actor.py / remote_function.py / function_manager / serialization|
+------------------------------------------------------------------+
|  Cython: _raylet.pyx + includes/*.pxd(声明) + includes/*.pxi(包装)|
+==================================================================+  <- _raylet.so
|  C++ core_worker  (CoreWorker / TaskSubmitter / TaskManager /    |
|                    ReferenceCounter / MemoryStore / PlasmaProv.) |
+------------------------------------------------------------------+
|  clients: gcs_rpc_client / raylet_rpc_client / raylet_ipc_client |
|           core_worker_rpc_client / object_manager_rpc_client     |
+------------------------------------------------------------------+
|  rpc (GrpcServer/ClientCallManager/Retryable) | pubsub | syncer   |
+------------------------------------------------------------------+
|  common (id / TaskSpec / LeaseSpec / RayConfig / scheduling)     |
|  asio / util / stats / observability / protobuf / flatbuffers    |
+------------------------------------------------------------------+

  服务端进程（独立可执行文件）:
    //src/ray/gcs:gcs_server   -> gcs_server_lib  -> gcs/*, store_client, pubsub, rpc
    //src/ray/raylet:raylet    -> raylet_lib      -> raylet/*, scheduling, object_manager, plasma
```

- `_raylet.so` 由根目录 `BUILD.bazel` L140-197 的 `pyx_library(name="_raylet")` 生成。依赖（L176-189）包括 `//src/ray/core_worker:core_worker_lib`、`//src/ray/gcs:gcs_server_lib`、`//src/ray/gcs_rpc_client:global_state_accessor_lib`、`//src/ray/pubsub:python_gcs_subscriber` 等。
- 全仓只有 5 个 `ray_cc_binary`：
  - `gcs_server`
  - `raylet`
  - `libcore_worker_library_java.so`
  - 两个测试或 bench 用的二进制

## 2. Python Core 层

### 2.1 `python/ray/_private/worker.py`
- `class Worker`（L444）：每个进程有一个全局实例 `global_worker`（L1397）。它持有 `core_worker`、`gcs_client`、`function_actor_manager` 和 mode。
- 主要函数与方法：

  | 函数/方法 | 行号 | 作用 |

  | `connect()` | L2493 | 创建 CoreWorker |
  | `get` | L2883 | — |
  | `put` | L3034 | — |

  | `Worker.put_object` | L806 | 序列化后调 C++ Put |

### 2.2 `python/ray/_private/node.py`、`services.py`
- `class Node`（`node.py` L77）管理本节点所有 Ray 进程。
  - `start_head_processes`（L1706）：依次启动 gcs_server、monitor、client server 和 dashboard。
  - `start_ray_processes`（L1739）：启动 log_monitor 和 raylet。
- `services.py`：
  - 可执行文件路径：`RAYLET_EXECUTABLE`、`GCS_SERVER_EXECUTABLE`（L61-66）。
  - 通用进程启动：`start_ray_process`（L879）。
  - 各进程的启动函数：`start_gcs_server`（L1542）、`start_raylet`（L1629）、`start_api_server`（L1227）、`start_monitor`（L2362）。

### 2.3 `remote_function.py` / `actor.py`
- `RemoteFunction`（`remote_function.py` L41）：`_remote()`（L361）在首次调用时导出函数，然后调用 `core_worker.submit_task`（L540）。
- `ActorClass`（`actor.py` L1557）：`_remote()`（L1886）调用 `core_worker.create_actor`（L2196），返回 `ActorHandle`（L2276）。
- `ActorMethod`（L846）：调用链是 `ActorHandle._actor_method_call`（L2488）→ `core_worker.submit_actor_task`（L2580）。

### 2.4 `function_manager.py`
- `FunctionActorManager`（L89）负责函数与类的导出和加载：
  - `export`（L219）、`export_actor_class`（L488）：pickle 后写入 GCS KV；
  - `get_execution_info`（L357）：执行端按 function descriptor 加载函数。

### 2.5 Cython 绑定层
- `python/ray/_raylet.pyx` 是唯一的主模块。它用 `include` 把 `includes/*.pxi` 拼进来（L186-205），用 `cimport` 引入 `includes/*.pxd` 中的 C++ 声明。
  - `.pxd`：`cdef extern from "ray/core_worker/core_worker.h"`，例如 `includes/libcoreworker.pxd` L125、L139 中的 `CCoreWorker`。
  - `.pxi`：Python 可见的 `cdef class` 包装，例如 `includes/object_ref.pxi` L50 中的 `ObjectRef`。
- Python 调 C++ 的形式统一为 `CCoreWorkerProcess.GetCoreWorker().Xxx(...)`。
- C++ 回调 Python 通过 `CCoreWorkerOptions` 中注册的函数指针，例如 `task_execution_callback = task_execution_handler`（L3298）。

## 7. RPC 与配置（`src/ray/rpc/`、`src/ray/common/`）

**服务端**
- `GrpcServer`（`grpc_server.h:94`）。
- 宏 `RPC_SERVICE_HANDLER`（L59）把 `Handle##HANDLER` 绑定到异步服务，并把请求 post 到 `main_service_`。这意味着各 Handler 都在单线程事件循环里执行。

**客户端**
- `ClientCallManager`（`client_call.h:196`）用多个 CompletionQueue 线程轮询，收到回复后把回调 post 回主事件循环。
- `GrpcClient`（`grpc_client.h:76`）配合 `INVOKE_RPC_CALL` 宏使用。
- `RetryableGrpcClient`（`retryable_grpc_client.h:81`）遇到瞬时网络错误时自动排队重试。

**配置**
- 定义在 `src/ray/common/ray_config.h:72-79`：`RAY_CONFIG(type, name, default)` 会生成成员变量，取值来自 `ReadEnv("RAY_" #name)`。
- 所有配置项都在 `ray_config_def.h` 中声明。
- `RayConfig::initialize(config_list)`（`ray_config.cc:31-77`）用 JSON 覆盖配置，遇到未知 key 会直接 FATAL。

## 8. 关键数据结构

### 8.1 ID 体系（`src/ray/common/id.h`）

```
JobID (4B)
  └─ ActorID   = 12B unique + JobID                 (id.h:124)
       └─ TaskID   = 8B unique + ActorID            (id.h:159)
            └─ ObjectID = 4B index + TaskID          (id.h:231)
PlacementGroupID = 14B unique + JobID               (id.h:300)
LeaseID          = 4B unique + 28B                  (id.h:330)
WorkerID / NodeID / FunctionID / ClusterID ...  由 id_def.h DEFINE_UNIQUE_ID 生成 (28B)
```

ObjectID 里嵌着 TaskID，所以能直接看出对象由哪个任务产生，这是 lineage 重建的基础。完整规范见 `src/ray/design_docs/id_specification.md`。
