# 01 项目架构概览

> 以下路径都相对仓库根目录 `/data/ruiqinchen/ray`。"L123" 表示行号，以当前工作区代码为准。

## 1. 项目定位

Ray 是用于扩展 AI 和 Python 应用的分布式计算框架，代码分三层：

- **C++ 核心运行时**（`src/ray/`）：包括 GCS、Raylet、CoreWorker、对象存储、RPC 等。
- **多语言前端**：
  - Python，位于 `python/ray/`，是主力语言；
  - Java，位于 `java/`；
  - C++ API，位于 `cpp/`，入口头文件是 `cpp/include/ray/api.h`。
- **上层 AI 库**（均在 `python/ray/` 下）：Data、Train、Tune、Serve、RLlib、LLM 等。

## 3. 运行时进程架构

```
                         +---------------------------------------------+
                         |                Head Node                    |
                         |                                             |
  +-----------+  gRPC    |  +--------------+    +-------------------+  |
  |  Driver   |--------->|  |  gcs_server  |<-->| Redis / RocksDB / |  |
  | (python   |          |  | (GcsServer)  |    | InMemory Store    |  |
  |  script)  |          |  +------^-------+    +-------------------+  |
  | CoreWorker|          |         | gRPC + pubsub + ray_syncer        |
  +-----+-----+          |  +------+-------------------------------+   |
        |                |  |  raylet (NodeManager)                 |   |
        | Unix socket    |  |  - WorkerPool                         |   |
        | (flatbuffers)  |  |  - ClusterLeaseManager / Local...     |   |
        +--------------->|  |  - ClusterResourceScheduler           |   |
        | plasma socket  |  |  - ObjectManager (Push/Pull)          |   |
        |                |  |  - LocalObjectManager (pin/spill)     |   |
        |                |  |  - [thread] PlasmaStore (shared mem)  |   |
        |                |  +------+--------------------------------+  |
        |                |         | fork/exec (python_worker_command) |
        |                |  +------v------+  +------v------+           |
        +--------------->|  | Worker proc |  | Worker proc |  ...      |
        gRPC PushTask    |  | CoreWorker  |  | CoreWorker  |           |
       (direct to worker)|  +-------------+  +-------------+           |
                         |                                             |
                         |  dashboard (head) / dashboard agent         |
                         |  monitor.py (autoscaler) / log_monitor      |
                         +---------------------------------------------+
                                       |  ObjectManager gRPC (Push/Pull)
                                       v
                         +---------------------------------------------+
                         |  Worker Node: raylet + workers + agent ...  |
                         +---------------------------------------------+
```

各组件要点：

- **gcs_server**：集群控制面，管理节点、Actor、Job、Placement Group、Worker、内部 KV 和 Task 事件。
  - 入口：`src/ray/gcs/gcs_server_main.cc:60`。
- **raylet**：每个节点一个，负责本地调度、Worker 池和对象管理。
  - 入口：`src/ray/raylet/main.cc:189`。
  - plasma store **不是独立进程**，在 raylet 进程里单开一个线程运行（`src/ray/object_manager/object_manager.cc:37-58`，`plasma/store_runner.h:78` 是全局单例）。
- **CoreWorker**：以库的形式链接进 `_raylet.so`，driver 和每个 worker 进程各有一个实例。
  - Bazel target：`//src/ray/core_worker:core_worker_lib`，链接关系见 `BUILD.bazel:140`。
- **Python worker 进程**：由 raylet 通过 `--python_worker_command` 拉起，入口是 `python/ray/_private/workers/default_worker.py`。启动命令在 `services.py` L1835-1854 构造。
- **dashboard / agent / monitor / log_monitor**：Python 进程，由 `python/ray/_private/services.py` 的 `start_*` 函数拉起。
- **Ownership 模型**：发起任务的 worker 就是返回对象的 owner，负责引用计数和对象位置（`ReferenceCounter`、`OwnershipBasedObjectDirectory`）。
  - Actor task 不经过 raylet，提交方直接 gRPC 推送到 actor worker。
