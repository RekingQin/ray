# 04 开发与测试指南

> 路径都相对仓库根目录 `/data/ruiqinchen/ray`。官方原文见 `doc/source/ray-contribute/development.md` 和 `getting-involved.md`。

## 1. 构建系统

### 1.1 Bazel

- 版本锁定为 **7.5.0**：见 `.bazelversion`，`WORKSPACE` L81 也会做版本检查。推荐用 bazelisk。
- 依赖用 WORKSPACE 管理，没有启用 bzlmod：`.bazelrc` L5-6。
- 三方依赖都在 `bazel/ray_deps_setup.bzl` 声明，包括 grpc 1.58.0、abseil、protobuf、flatbuffers、gtest 1.14.0、cython 3.0.12、otel-cpp 1.19.0。
- 自定义宏：
  - `bazel/ray.bzl`：`ray_cc_library`（L141）、`ray_cc_test`（L150，默认依赖 `ray_gtest_main`）、`ray_cc_binary`（L172）
  - `bazel/python.bzl`：`py_test_module_list`（L73）、`doctest`
- `.bazelrc` 默认值：`-c opt`（L45）、C++17、`-Werror`（L89-90）。
- `.bazelrc` 中常用的 config：

  | config | 用途 |
  |---|---|
  | `--config=debug` | 调试构建 |
  | `--config=asan` / `asan-build` | AddressSanitizer |
  | `--config=tsan` | ThreadSanitizer，会关闭 jemalloc |
  | `--config=ubsan` | UBSan |
  | `--config=llvm` | 使用 libc++ |
  | `--config=ci` | CI 用，开启 flaky 重试并禁用测试缓存 |

- 根目录 `BUILD.bazel` 中的关键 target：

  | target | 作用 |
  |---|---|
  | `//:_raylet` | `pyx_library`（L140），生成 `_raylet.so` |
  | `//:ray_pkg_zip` | 打包 raylet、gcs_server 和 `_raylet.so` |
  | `//:gen_ray_pkg` | 构建上述产物，并解压到 `python/ray/` |
  | `//:gen_py_proto` | 只生成 Python protobuf |
  | `//:refresh_compile_commands` | 生成 clangd 用的 `compile_commands.json` |

### 1.2 常用构建命令

```bash
# 完整源码开发安装（会调用 bazel 构建 C++）
cd python/ray/dashboard/client && npm ci && npm run build && cd -   # dashboard 前端
cd python && pip install -r requirements.txt
pip install -e . --verbose
# CI 写法（ci/ci.sh）:
pip install -q cython==3.0.12
pip install -v -e . -c requirements_compiled.txt --config-settings editable_mode=compat

# 只重建 C++ 产物并放回 python/ray
bazel run //:gen_ray_pkg
bazel run -c fastbuild //:gen_ray_pkg      # 快速构建
bazel run --config=debug //:gen_ray_pkg    # 调试构建
bazel run //:gen_py_proto                  # 只改 proto 时
bazel run //:refresh_compile_commands      # clangd 支持

# 只改 Python 代码：先装 nightly wheel，再把源码软链接进 site-packages
pip install -U <nightly wheel url>
python python/ray/setup-dev.py -y [--skip _private dashboard]

# 打 wheel / 镜像
./build-wheel.sh 3.12
./build-image.sh ray -p 3.12
```

`setup.py` 会读取以下环境变量（`python/setup.py` L29-35、L111-123、L590-595）：

| 变量 | 作用 |
|---|---|
| `SKIP_BAZEL_BUILD=1` | 跳过 bazel |
| `RAY_INSTALL_JAVA=1` | 额外构建 Java |
| `RAY_INSTALL_CPP=1` | 安装 ray-cpp |
| `RAY_DISABLE_EXTRA_CPP=1` | 不构建 C++ API |
| `RAY_BUILD_REDIS` | 默认 1 |
| `BAZEL_ARGS` | 透传给 bazel 的参数 |
| `RAY_DEBUG_BUILD=debug\|asan\|tsan` | 调试或 sanitizer 构建 |
| `BAZEL_PATH` | 指定 bazel 可执行文件 |

## 2. 依赖管理（三层）

依据 `doc/source/ray-contribute/dependency-management.md`：

```
Layer1 源文件:   python/requirements.txt, python/requirements/**/*.txt  (人工编辑)
        │  ci/ci.sh compile_pip_dependencies
        ▼
Layer2 约束:     python/requirements_compiled.txt  (+ _py3.14 单独编译)
        │  ci/raydepsets (uv pip compile; configs/*.depsets.yaml)
        ▼
Layer3 锁文件:   python/deplocks/**/*.lock
```

```bash
ci/ci.sh compile_pip_dependencies                         # 要求 x86_64 Linux 加 Python 3.11
bazelisk run //ci/raydepsets:raydepsets -- build --all-configs
bazelisk run //ci/raydepsets:raydepsets -- build --all-configs --check
```

- 改 `requirements.txt` 的 install_requires 部分时，要同步修改 `setup.py` 中的 `install_requires`。
- 不要手改 compiled 文件和 lock 文件。

## 3. 代码规范与 Lint

- Python 用 ruff（行宽 88）、black 22.10.0 和 isort 规则，配置在 `pyproject.toml`。类型检查用 mypy（autoscaler、serve 子集）和 pyrefly（data，见 `pyrefly.toml`）。
- C++ 用 clang-format v12，基于 Google 风格，ColumnLimit 90（`.clang-format`）。另有 cpplint 和 clang-tidy（`.clang-tidy`）。
- Bazel 用 buildifier，Shell 用 shellcheck，Java 用 spotless/checkstyle，前端用 prettier/eslint。

```bash
pip install -U pre-commit==3.5.0 && pre-commit install
pre-commit run                                  # 只检查暂存文件
./ci/lint/lint.sh pre_commit
./ci/lint/lint.sh clang_format
./ci/lint/bazel-format.sh
./ci/lint/check-git-clang-tidy-output.sh
./setup_hooks.sh                                # 安装 prepare-commit-msg(自动 DCO) 和 pre-push
```

## 4. 测试

### 4.1 Python（pytest）

- 全局配置在 `pytest.ini`：`timeout = 180`（L13）、`asyncio_mode = auto`。
- 测试位置：Core 的测试在 `python/ray/tests/`，各库的测试在各自目录的 `tests/` 下（例如 `python/ray/data/tests/`，这个位置由 pre-commit 强制）。
- 常用 fixture 都在 `python/ray/tests/conftest.py`：

| fixture | 行号 | 说明 |
|---|---|---|
| `shutdown_only` | L562 | 测试结束后 `ray.shutdown()` |
| `ray_start_regular` | L656 | 单节点，可参数化 |
| `ray_start_regular_shared` | L673 | module 级共享 |
| `ray_start_2_cpus` / `ray_start_10_cpus` | L687 / L694 | — |
| `ray_start_cluster` / `ray_start_cluster_head` / `ray_start_cluster_2_nodes` | L739 / L769 / L809 | 用 `Cluster()` 模拟多节点 |
| `call_ray_start` | L832 | 走 CLI `ray start` |
| `ray_start_chaos_cluster` | L1213 | 混沌测试 |

```bash
pip install -c python/requirements_compiled.txt -r python/requirements/test-requirements.txt
python -m pytest -v -s python/ray/tests/test_basic.py           # 用 python -m pytest
python -m pytest -v -s python/ray/tests/test_basic.py::test_xxx
```

- 在 Bazel 中注册测试：在 `python/ray/tests/BUILD.bazel` 的 `py_test_module_list(files=[...], tags=["team:core", ...])` 里添加，`team:*` 标签必填（`ci/lint/lint.sh bazel_team` 会检查）。

### 4.4 CI

- `.buildkite/*.rayci.yml` 按领域拆分为 core、data、serve、ml、rllib、doc、lint、windows 等，由 rayci 编排。
- 哪些改动跑哪些测试，由 `.buildkite` 下的 `test.rules.txt` 和 `always.rules.txt` 决定。
- 测试在容器内运行，例如：`bazel run //ci/ray_ci:test_in_docker -- //python/ray/tests/... core`。
- PR 默认只跑 microcheck。在 commit message 中写 `@microcheck //target` 可以追加测试；合并前需要加 `go` 标签跑全量（`doc/source/ray-contribute/ci.md`）。

## 5. Benchmark

```bash
bazel run -c opt //:gen_ray_pkg           # ray_perf.check_optimized_build 会检查是否为 opt 构建

# 核心 microbenchmark（scripts.py L2292 → python/ray/_private/ray_perf.py main L95）
ray microbenchmark
TESTS_TO_RUN="single client get" ray microbenchmark      # 过滤项见 ray_microbenchmark_helpers.py L12-13
TESTS_TO_SKIP="..." ray microbenchmark

# release 中的 microbenchmark
cd release/microbenchmark && RAY_ADDRESS=local TEST_OUTPUT_JSON=/tmp/mb.json python run_microbenchmark.py
python run_microbenchmark.py --experimental              # 包含 compiled graph 等

# 可扩展性 benchmark（release/benchmarks）
cd release/benchmarks
python single_node/test_single_node.py
SMOKE_TEST=1 python distributed/test_many_actors.py
python distributed/test_many_tasks.py --num-tasks=1000

# GCS 存储 microbench（C++）
bazel run //src/ray/gcs/store_client/tests:storage_microbench
```

- 完整的 release 测试定义在 `release/release_tests.yaml`，例如 microbenchmark 在 L2827、many_tasks 在 L3598。它们通过 `release/ray_release/` 在 Anyscale 集群上运行，本地一般无法直接执行。
- 其他 benchmark 目录：`release/nightly_tests/`、`release/benchmark-worker-startup/`、`release/perf_metrics/`。
