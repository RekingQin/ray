链路上的几个设计点：

- worker lease 按 **SchedulingKey**（调度类加依赖等）复用：同一 key 的任务可以连续推给已经租到的 worker，省掉重复调度。
- 调度分**两级**：ClusterLeaseManager 选节点，选到其他节点时 spillback；LocalLeaseManager 负责本地资源和参数。
- 任务数据**不经过 raylet**。raylet 只授予 lease，任务通过 PushTask 由 owner 直接推给 worker。

### 5.4 对象生命周期
- `ObjectRef.__init__` 调用 `add_object_ref_reference`，`__dealloc__` 调用 `remove_object_ref_reference`（`includes/object_ref.pxi` L56-77）。这两步驱动 C++ `ReferenceCounter`。
- 引用计数归零后，owner 通知释放对象。
- 内存不足时，raylet 的 `LocalObjectManager` 把对象 spill 到外部存储（`SpillObjectUptoMaxThroughput`，`local_object_manager.cc:145`），需要时再恢复（`AsyncRestoreSpilledObject`，:440）。
  - spill 和 restore 由专门的 SPILL/RESTORE 类型 worker 执行（`default_worker.py` L211-218、L253-263）。
- 对象丢失时由 `ObjectRecoveryManager::RecoverObject`（`object_recovery_manager.cc:24`）按 lineage 重新提交任务。

## 7. RPC 线程模型

```
gRPC CompletionQueue 线程(s) ──post──▶ instrumented_io_context (main_service, 单线程事件循环)
                                          ├─ ServerCall: Handle<RPC>(...)   (rpc/grpc_server.h RPC_SERVICE_HANDLER)
                                          └─ ClientCall 回调                 (rpc/client_call.h ClientCallManager)
```

GCS、raylet 和 CoreWorker 都采用这种模型：业务逻辑大多跑在单线程 asio 事件循环里。这就要求 Handler **不能阻塞**，耗时操作只能用异步回调来做。
